# Аудит среды перед развёртыванием

Дата: 23.10.2026. Ниже — очищенный обзор завершённого read-only этапа. Домашние адреса, MAC, fingerprints, реальные имена узлов и VMID намеренно не включены. Подробные исходные отчёты хранятся локально вне публикуемого комплекта.

**Это исторический снимок до создания стенда, а не текущий статус.** После отдельного согласования созданы две VM, закреплены новые leases, проверены recovery/VPN/SSH и базовые WAF/логи. Source template сохранён, PVE firewall глобально не менялся. Последующие факты и ограничения — в [worklog.md](worklog.md) и [verification.md](verification.md); прежние неизвестные ниже относятся именно к моменту read-only аудита.

## Что подтверждено

- Пользователь установил отдельно согласованный SSH public key. Авторизованный административный сеанс подтверждён; существующий парольный доступ гипервизора не отключался.
- Proxmox VE `9.1.1`, kernel `6.17.2-1-pve`. Это наблюдённые версии среды, а не выбранные версии компонентов будущего стенда.
- Гипервизор online; API сообщает 40 logical CPU. Моментная загрузка CPU около 0,92%.
- Usable RAM — 62,84 GiB; дополнительный снимок показывает 58,59 GiB available. Это наблюдение, а не резервирование.
- Для VM-дисков доступен активный LVM-thin storage: 347,90 GiB total, 334,43 GiB available. Thin data usage — 3,87%, metadata usage — 0,60%.
- Отдельно свободно около 16,0 GiB extents volume group. **Это другая величина, не свободное место внутри thin pool.**
- Directory storage имеет около 80,46 GiB свободного места для поддерживаемых типов содержимого, включая образы и backup.
- Существующий LAN bridge активен. Два candidate VMID проверены на момент аудита, но не зарезервированы.
- Существующий cloud-init template помечен как template и generic Linux; происхождение и установленная ОС не установлены.

Ресурсов по этим снимкам достаточно для предлагаемого небольшого стенда. Нагрузочное тестирование и аппаратная диагностика storage не выполнялись.

## Firewall и изоляция

PVE firewall status — `disabled/running`. Наличие active служб не означает включённую защитную политику. В просмотренном native nftables ruleset нет таблиц/цепочек/правил; просмотренные legacy IPv4 raw/filter цепочки пусты с политиками ACCEPT. Legacy IPv6 firewall не проверялся.

На текущий firewall гипервизора нельзя опираться как на доказанную изоляцию новых VM. Его глобальное включение не входит в read-only аудит и могло бы затронуть существующие сервисы.

Предварительный вариант использует существующую LAN и отдельные VM/диски. Guest firewall должен закрывать лишние входящие соединения и обеспечивать VPN-only SSH. Это **общая L2**, а не отдельный VLAN или защищённый сегмент. При разрешённом OUTPUT гости смогут обращаться к домашней LAN. Более строгая сегментация или egress-ограничения требуют отдельного плана; существующая изоляция ещё не обещается и не считается проверенной.

## Предложенные размеры на момент аудита

| Узел | CPU | RAM | Отдельный диск | Предварительная роль |
|---|---|---|---|---|
| ubu1 | 1 socket × 2 cores | 2048 MiB, balloon 0 | 20 GiB | Nginx, ModSecurity, CRS, Alloy, WG peer |
| ubu2 | 1 socket × 2 cores | 4096 MiB, balloon 0 | 30 GiB | WG hub, native Loki/Grafana |

Суммарно 4 vCPU, 6 GiB RAM и 50 GiB дисков. Предварительно выбрана Ubuntu 24.04 LTS. Точные image/checksum, версии компонентов и зависимости предстоит зафиксировать. Это решения проекта, а не дополнительные требования работодателя.

Thin storage не резервирует физические блоки для каждой VM заранее. Рост дисков, snapshots и логов влияет на общий pool и существующих потребителей. Нужны пределы хранения access/audit/container/journal logs, Loki retention, контроль свободного места и ограниченный срок хранения снимков. Проверка discard/fstrim и storage policy относится к будущей реализации.

## Что было неизвестно на момент аудита

- Console recovery не проверено; успешный SSH не заменяет подтверждённый способ восстановления.
- ОС, происхождение и доверенность имеющегося template не установлены. Настроенный guest agent не доказывает, что он установлен и работает внутри.
- LAN адреса новых VM, постоянный endpoint VPN hub и непересекающаяся VPN-подсеть не выбраны. DHCP-пул широк; static внутри действующего пула нельзя назначать без согласованного резервирования/исключения. Dynamic lease не гарантирует неизменный endpoint после перезагрузки.
- CPU model, firmware, консоль и прочие точные параметры bootstrap должны быть записаны до создания.
- Guest firewall, IPv6-политика, WireGuard, веб/WAF и доставка логов ещё не развёрнуты и не проверены.
- Аппаратное состояние storage, I/O под нагрузкой и политика автоматического расширения thin pool полностью не исследованы.

## Граница разрешения и следующий этап на момент аудита

Согласование audit-ключа распространяется на отдельно разрешённый доступ и read-only аудит. Оно **не разрешает** создание/изменение VM, сети, firewall, template, дисков или постоянной авторизации. Проверенные candidate ID не являются резервированием.

Следующий шаг — дополнить [план согласования](approval-plan.md) конкретными объектами, адресами, источником образа, потоками и откатом; подтвердить console recovery и получить разрешение на изменения. Затем создавать только новые объекты и выполнять [приёмочные проверки](verification.md). VM стенда ещё не созданы; инфраструктурные требования остаются невыполненными. Перезагрузка и публикация результатов требуют отдельных согласований.
