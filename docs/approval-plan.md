## A. Доступ для завершения аудита

Для Proxmox создан отдельный ed25519 ключ `~/.ssh/ozzylogik-proxmox`; отдельный `~/.ssh/ozzylogik-lab` уже используется для новых VM. Приватные файлы остаются в WSL вне проекта, mode0600. Пароли и private keys в чат не отправлялись. Automation key без passphrase защищается локальными правами WSL; публичная часть0644.

Публичную часть пользователь добавляет самостоятельно через доверенную консоль/существующий SSH-сеанс Proxmox в authorized_keys root. По согласованному решению ключ без forced-command, то есть даёт полноценный root SSH-доступ. Вариант restricted audit-key был предложен и пользователем не выбран. При этом первые команды агента после установки — только read-only аудит.

Наблюдённый в сети fingerprint сохранён только в `.local/`; он совпал с существующей ED25519 записью Windows known_hosts. Для read-only SSH из WSL можно сослаться на этот файл без копирования и без отключения StrictHostKeyChecking. Если пользователь не доверяет истории этой записи, сверить через доверенную консоль: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Нельзя автоматически доверять одному ssh-keyscan.

Объём первого доступа: только чтение ресурсов, storage, bridge, существующих VMID и маршрутов. Авторизация Proxmox не меняется, парольный вход root сохраняется. Откат: удалить только добавленную строку public key; затем удалить отдельный приватный ключ из WSL по решению владельца. Существующие ключи и строки authorized_keys не трогать.

**Способ согласован; ключ установлен, авторизация и read-only аудит ресурсов выполнены. Агент не менял настройки SSH/авторизации гипервизора.**

Созданы ubu1 VM101 с2 vCPU/2 GiB/20 GiB и ubu2 VM102 с2 vCPU/4 GiB/30 GiB; фиксированная RAM, отдельные full-clone диски. Свобода ID была проверена перед созданием; повторный запуск clone для текущих VM недопустим. Домашние LAN/MAC остаются только в локальном inventory и операционных записях.

Ресурсов достаточно; thin data usage 3,87%, metadata usage 0,60%. Свободное место внутри thin pool не путать со свободными extents VG и не считать зарезервированным.

До клонирования пользователь подтвердил provenance template9000: официальный Ubuntu24.04 источник и исходную checksum-проверку; текущие PVE-параметры сверены. Source не запускался/не менялся. ## D. Сеть, SSH и firewall новых VM

Согласованный сетевой/SSH-переход выполнен:

1. Основной WG endpoint ubu2 доступен локально. Два согласованных WAN DNAT подготовлены disabled; включение только на ограниченную demo-сессию, не во время обычного bootstrap.
2. WG hub ubu2, peers WSL/ubu1, маршруты /32, без NAT внутри VPN.
3. Ключевой доступ labadmin, sudo; запрет root/password/keyboard-interactive на обеих VM.
4. ubu1 SSH только через wg0 с ADMIN_WG; ubu2 после bootstrap также управляется через VPN.
5. INPUT/FORWARD default deny, конкретные потоки из architecture; поведение OUTPUT и IPv6 явно зафиксировано.
6. Временное bootstrap-правило ограничено управляющим источником и удаляется после проверки нового пути.

Риск: потеря SSH при ошибке AllowedIPs, маршрутов, интерфейсов, прав ключа или firewall. Снижение риска: доступная Proxmox console, проверка новых подключений до запрета старого пути, сохранённые настройки, автоматический откат через systemd timer. Таймер отменяется только после проверки из VPN и обычной LAN. Существующий established-сеанс не заменяет эти проверки.

Фактически secure и commit завершены; новые VPN SSH/отрицательные LAN22/auth-пробы прошли. Оба guard после commit clear, pending snapshot отсутствует, timers inactive/disabled. Это разрешение не распространяется на чужие VM, storage, существующие WG peers или авторизацию Proxmox.

Откат: console → восстановление сохранённых sshd/nftables/WG конфигураций → проверка синтаксиса → reload; при необходимости восстановление согласованного снимка только тестовой VM. Снимки не считаются полноценным backup.
