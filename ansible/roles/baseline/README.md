# baseline: guest account, SSH policy and access rollback

The role targets only the two new Ubuntu guests; never Proxmox or the router. It requires `ansible.posix` for `authorized_key`. Bootstrap and secured phases have been applied; fresh VPN administrative SSH/sudo, effective SSH policy and separate root/password/keyboard-interactive refusals were checked, including after the approved reboots.

`lab_phase` is mandatory. In `bootstrap`, install the supplied public key and the dedicated `lab_admin_user` with passwordless sudo, bound journal storage, and install rollback tooling. Existing SSH authentication policy is retained. In `secured`, require `lab_vpn_verified=true`, `lab_console_recovery_verified=true`, `ansible_user=lab_admin_user` and `ansible_host` equal to this VM's VPN IP. Only then apply SSH root/password/keyboard-interactive denial and verify effective admin/root contexts before reloading. The account has full administrative sudo for this lab; it is not a restricted reviewer account.

Inputs: `lab_admin_public_key` (public string), optional `lab_admin_additional_public_keys` (public strings), `lab_admin_user`, `lab_hub_wg_ip`, `lab_web_wg_ip`, `lab_admin_wg_ip`, `lab_vpn_interface`. Supply secret variables through an external local vars/vault file; this role does not generate or store repository credentials. `lab_apt_package_versions` optionally maps Ubuntu package names to exact versions; otherwise packages use `state=present` from the selected repositories, never `latest`. Record/approve the repository and resolved package versions before applying.

Order: bootstrap baseline → firewall → wireguard; verify a new VPN admin connection; secured baseline → firewall; independently verify fresh VPN success, Windows LAN SSH failure and authentication refusals; only then run the firewall `commit` phase. Do not spend the rollback interval on installing unrelated services. Default transaction timeout is 900 seconds, constrained to 300–3600 seconds; a pending transaction is never silently extended.

`/usr/local/sbin/ozzylogik-access-guard arm|status|rollback|commit` is a fixed guest-only helper. Before network/SSH mutation it saves six managed access files, their metadata, its own nft table, IPv4/IPv6 forwarding values and the owned services' state. Secret-bearing snapshots are root-only under `/var/lib/ozzylogik/access-rollback/pending`. A systemd timer invokes `rollback` locally even if SSH is lost. If the guest reboots while pending, the enabled timer starts a new timeout after boot; this is bounded recovery, not a durable absolute deadline. Reboot during an uncommitted transition is not part of the procedure.

Rollback restores only its allowlisted files/table/services and reloads validated SSH; it never flushes all nftables rules, changes users' keys or touches the hypervisor. A failed rollback retains the snapshot for console recovery. `commit` deletes the snapshot and disables the timer; use only after external tests. A recovery path must be confirmed before applying; QEMU Guest Agent command execution was verified for this lab. Arm/commit completed, and absence of pending snapshots plus disabled/inactive timers was checked again after reboot. These successful checks do not demonstrate a deliberately forced timed rollback.

The `00-ozzylogik.conf` drop-in is checked against the complete `sshd -T` result so conflicting earlier directives or `Match` rules cause a failure and rollback request. Check mode does not prove connectivity or authentication.

References: [systemd monotonic timers](https://www.freedesktop.org/software/systemd/man/255/systemd.timer.html), [sshd configuration](https://man.openbsd.org/sshd_config).
