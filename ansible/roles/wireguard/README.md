# wireguard: two-guest VPN

The role configures `ubu2` (group `monitoring`) as hub and `ubu1` (group `web`) as a peer. WSL/reviewer client configurations are managed separately by the controller workflow. It requires baseline guard tooling and the bootstrap firewall first. It never creates keys or changes the router.

Required address inputs: `lab_vpn_interface`, `lab_vpn_prefixlen=29`, `lab_hub_wg_ip`, `lab_web_wg_ip`, `lab_admin_wg_ip`, `lab_hub_lan_ip`, plus `lab_reviewer_wg_ip` when `lab_reviewer_enabled=true`. `lab_wireguard_port=51820`, guest MTU 1420 and keepalive 25 seconds are defaults. Candidate addresses must be approved/rechecked against routes before applying. This lab uses guest MTU1420 and WSL client MTU1200 because its outer interface MTU is 1280; the original client MTU1420 stalled SSH key exchange. Fresh VPN SSH/sudo to both guests passed after correction and after the approved reboots. The reviewer peer is disabled by default; the current lab enables it for the Windows LAN test with a host-level `lab_reviewer_enabled: true` override on both guests. Inventory `all.vars` does not override the false value in project `group_vars`.

Supply `lab_wg_hub_private_key`, `lab_wg_web_private_key` and matching `lab_wg_hub_public_key`, `lab_wg_web_public_key`, `lab_wg_admin_public_key` through the external local secret vars file. Enabling reviewer also requires `lab_wg_reviewer_public_key`. Admin/reviewer private keys are never used on the guests. Private templates use `no_log`, no diff and root 0600; snapshots remain root-only. The offline validator checks supplied key pairing through `wg pubkey`, peer address overlap and absence of LAN/default AllowedIPs without creating any interface.

Interface addresses use the small `/29` prefix; all peers' AllowedIPs are individual `/32` VPN addresses. Hub peers have no preconfigured external Endpoint: authenticated traffic teaches endpoints. The web peer connects to the reserved hub LAN address. No NAT, LAN route, default route or PostUp firewall shell is installed. IPv4 forwarding is enabled only on the hub; IPv6 forwarding is disabled on both guests.

Changed configuration restarts `wg-quick` under the shared rollback transaction. That can briefly interrupt the tunnel; do not apply from the VPN until the separate verification/recovery gates are satisfied. No-change runs do not restart or rearm. Package versions may be supplied via `lab_apt_package_versions`; otherwise record the selected Ubuntu package versions before applying.
