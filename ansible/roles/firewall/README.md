# firewall: guest nftables policy

Only the new guests are in scope. The role owns `table inet ozzylogik`, its configuration, loader and persistence unit. Atomic reload deletes/recreates only that table in one `nft -f` transaction, preceded by `nft -c -f`; it never uses `flush ruleset` and never enables PVE firewall. Existing global guest firewall managers are not disabled automatically: use clean approved guests and inspect the complete ruleset before accepting results.

Required inputs: `lab_phase=bootstrap|secured|commit`, inventory groups `web`/`monitoring`, `lab_admin_user`, `lab_lan_interface`, `lab_bootstrap_admin_lan_ip`, `lab_hub_lan_ip`, `lab_web_lan_ip`, `lab_dns_ipv4` (list of approved router DNS IPv4 addresses), `lab_dhcp_server_ipv4`, `lab_hub_wg_ip`, `lab_web_wg_ip`, `lab_admin_wg_ip`, `lab_vpn_interface`; reviewer enabled additionally needs `lab_reviewer_wg_ip`. Console recovery must already be verified. All interfaces/addresses must be actual approved values, not guesses.

INPUT/FORWARD/OUTPUT default drop. Bootstrap permits LAN SSH only from the observed Windows LAN source. Secured requires a previously verified new VPN connection and removes that exception before tests/commit. TCP service interface checks precede generic established acceptance, preventing an established tuple from admitting LAN SSH packets. Administrative VPN sources can reach SSH on both guests, HTTP on web and Grafana on hub; only web can push Loki logs. Hub accepts IPv4 WireGuard UDP from any outer source; cryptographic peer keys/AllowedIPs control tunnel membership. The router WAN DNAT remains a separate disabled-by-default action.

Hub forwarding is only `wg→wg`, admin/reviewer→web TCP22/HTTP and reverse established/related traffic. No LAN forwarding or NAT. OUTPUT allows exact router DNS/DHCP, the required outer WG flows, Loki push and constrained VPN replies, then blocks private/special destinations before public established traffic and public NTP/HTTP/HTTPS. Hub's learned public WG endpoints can use translated/random destination ports; outbound UDP source port is the WG service port. Rules do not prevent a root compromise from disabling a guest firewall and do not create L2 segmentation.

IPv6 application ingress/egress is denied, with only link-local neighbor discovery preserved. Link-local DHCPv6 is opt-in through `lab_dhcpv6_enabled`, false by default; IPv6 forwarding has no exception. Verify actual IPv6 behavior on the guests.

`lab_demo_http_enabled=false` by default. When explicitly enabled on web, `lab_demo_http_sources` defaults to all IPv4 sources because the reviewer's external address is initially unknown; narrow it when known. This is a deliberate temporary exposure and must be turned off after the demo along with router DNAT. Guest config alone never publishes the router. Other configurable ports: `lab_http_port` defaults to `lab_web_http_port`/80, `lab_grafana_port=3000`, `lab_loki_port=3100`.

Use `commit` only with `lab_access_checks_passed=true` after independent new-session VPN+/Windows-LAN− and SSH-authentication checks. It disables the pending guard timer; it does not perform those external tests. The snapshot must remain armed during deletion of the bootstrap exception. These checks and commit have run successfully; listed VPN/LAN IPv4/IPv6 TCP port checks, authentication refusals and guard-clear state were checked again after the approved reboots. This is not an exhaustive TCP/UDP scan or separate L2 isolation.

Reference: [nftables atomic rule replacement](https://wiki.nftables.org/wiki-nftables/index.php/Atomic_rule_replacement).
